# 納品ファイルの保管ルール（Googleドライブ）

出品して売るファイル（Excel・HTML・PDFなど）は、**Googleドライブに一元管理する**。
iPhoneから片手で取り出して、そのままココナラのトークルームに添付できる状態を保つ。

---

## 0. 最重要：ドライブは保管庫であって、納品経路ではない

**共有リンクを購入者に渡さないこと。**

ココナラの利用規約は、やりとりを全てココナラ内で行うよう定めている。
出品編集画面にも「直接会う行為やEメール、SNS、Zoomなどの外部ツールを用いた
やりとりは禁止です」と明記されている。

- ドライブ … 自分がファイルを保管し、iPhoneから取り出すための場所
- 納品 … **ココナラのトークルームにファイルを添付する**

ドライブのファイルは、共有設定を変更しない（自分だけがアクセスできる状態のまま）。

---

## 1. フォルダ構成

```
ココナラ/
├── 1_納品ファイル/          ← 売れたらここから取り出して添付する
│   ├── 建設帳票5点セット/
│   └── 診断テンプレート3種/
├── 2_出品素材/
│   ├── 画像/               ← 出品ページに登録した画像
│   └── 出品文面/           ← タイトル・本文・オプションのテキスト
└── 3_作業中/               ← 未公開・検証待ちのもの
```

**`1_納品ファイル/` に置いてよいのは、そのまま送れる状態のものだけ。**
検証が終わっていないものは `3_作業中/` に置く。ここを混ぜると事故が起きる。

## 2. 「そのまま送れる状態」の定義

Excelファイルは、次の2つを両方満たしてはじめて `1_納品ファイル/` に移す。

1. **数式の検証が終わっている**（`formulas` パッケージで計算し、不一致0件）
2. **一度Excelで開いて上書き保存してある**

2つ目を飛ばすと、購入者の画面でセルが空に見える。生成した .xlsx には
計算結果のキャッシュが入っていないため、開くまで値が表示されないことがある。

**開いて保存し直したファイルで、ドライブ上のものを差し替える。**
生成したままのファイルを置いたままにしない。

## 3. ファイル名

```
建設帳票5点セット_v1.zip
工事別原価管理表_v1.xlsx
```

- 版は `_v1` `_v2` と数字で上げる。日付は入れない（更新のたびに名前が変わって追えなくなる）
- 前の版は消さず、同じフォルダに残す。購入者から「前のに戻して」と言われることがある
- セット物は**zipにまとめたものも一緒に置く**。1件の購入で5ファイル添付するより速い

## 4. 出品したら、その日のうちに置く

出品を公開したら、その場で `1_納品ファイル/` に納品物を入れる。
「売れてから用意する」にすると、初回の納期を落とす。

即納をうたう出品（お届け日数1日）は、**ドライブに置いていない時点で嘘になる。**

## 5. 出品素材も残す

`2_出品素材/出品文面/` に、出品ごとのテキストをそのまま置く。

```
F_建設帳票5点セット_出品文面.txt
```

出品ページは後から編集される。**何を書いて公開したかの記録が手元に残らないと、
反応が悪かったときに何を直したのか分からなくなる。**

## 6. リポジトリとの使い分け

| 置き場所 | 何を置くか |
|---|---|
| このリポジトリ | **生成スクリプト**（`_notes/portfolio-tools/`）と計画・ルール |
| Googleドライブ | **生成された成果物**（.xlsx / zip / 画像） |

リポジトリは public なので、**販売物そのものはコミットしない**。
`samples/` と `templates/` は `.gitignore` に入っている。

スクリプトさえリポジトリにあれば、成果物はいつでも作り直せる。
ドライブに置くのは「Excelで開いて保存し直した、そのまま売れる版」であって、
生成しただけのものではない。
