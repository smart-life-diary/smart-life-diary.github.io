# 出品支援セットの作り方（ルール）

ココナラ／クラウドワークス等の出品・応募フォームを埋めるための材料は、
**すべて「出品支援セット」の形式で出す**。散文で説明して終わりにしない。

スマートフォンから片手で貼り付けていく前提で作る。画面とこの文書を往復するだけで
フォームが埋まり切る状態がゴール。

---

## 1. 原則

| | ルール |
|---|---|
| 形式 | **入力欄1つにつき、コードブロック1つ。** 複数欄を1ブロックにまとめない |
| 順番 | **フォームの上から下へ。** 画面をスクロールする順と一致させる |
| 字数 | 各ブロックの見出しに `（実数／上限）` を必ず書く。**書く前に数える** |
| 選択式 | プルダウン・ラジオ・チェックボックスも、選ぶ値をコードブロックで出す |
| 画像 | ファイル名と**登録順**を明記する |
| 最後 | 貼り終えたか確認できるチェックリストで締める |

## 2. 字数は必ず機械で数える

目視で数えない。ブロックを出す前にスクリプトで検証し、その結果を見出しに書く。

```python
fields = {"タイトル(25)": ("...", 25), "サービス内容(1000)": ("...", 1000)}
for k, (v, lim) in fields.items():
    print(f'{"OK " if len(v) <= lim else "NG "}{k:<24}{len(v):>5}/{lim}')
```

**注意：フォームのカウンターは改行を数えないことがある。** 画面表示と手元の数が
数文字ずれても、上限に対して余裕があれば問題ない。ずれが大きいときは、
入力欄を下までスクロールして末尾が入っているか確認してもらう。

## 2.5. 文の途中で改行しない

コードブロックの見た目を整えるために文の途中で折り返すと、貼り付けた先では
**変な位置で改行された文章**になる。相手の画面幅は分からないので、こちらで
折り返す意味がない。

```
悪い例：
　建設コンサルタントとして15年、発注者との要件整理から
　成果品の納品までを担当してきました。

良い例：
　建設コンサルタントとして15年、発注者との要件整理から成果品の納品までを担当してきました。
```

改行を入れてよいのは、段落の切れ目と、箇条書きの各項目だけ。

## 3. 上限は推測しない

字数上限・カテゴリ名・選択肢は、**画面か公開データで確認してから書く**。

これまで実際に外した箇所：

| 推測した内容 | 実際 |
|---|---|
| 画像の表示比率 4:3 | **1.20:1**（プレビューを実測して判明） |
| サービスタイトル 30字 | **25字** |
| キャッチコピー 25字 | **15〜30字** |
| 管理表・フォーマット作成は「業務自動化・効率化支援」の下 | **データ分析・集計代行**の下 |
| 手法はチェックボックス（複数選択可） | **ラジオボタン（1つだけ）** |
| カテゴリ「IT・プログラミング・開発」 | そんなカテゴリは無い（**IT相談・システム開発**） |
| トークルーム回答例はタイトル＋本文 | **タイトル欄は無い。「購入者側」「出品者側」のペアで各300字** |

分からないときは「その選択肢の一覧を送ってください」と頼む。埋めてから直すより速い。

## 4. 「その他」を選ばせない

カテゴリタイプで `その他（〜）` を選ぶと、一覧の最後尾グループに落ちる。
候補が6つしかなくても、消去法で1つに絞って指定する。

**コンテンツ出品のカテゴリは購入後に変更できない。** ここだけは推測で決めない。

## 5. セットに必ず含めるもの

```
□ カテゴリ（大・中・小の3段すべて）
□ タイトル
□ キャッチコピー
□ 本文（サービス内容 / 説明文）
□ 価格・納期・受注可能件数・無料修正回数
□ カテゴリ固有の必須項目（手法・業種など。カテゴリを変えると出現する）
□ 有料オプション（名称／金額／追加日数）
□ 購入にあたってのお願い
□ よくある質問
□ 見積りにあたってのお願い
□ チェックボックスの ON / OFF
□ 画像のファイル名と登録順
□ 動画（任意。YouTubeのURLのみ。「動画を優先して表示する」は原則OFF）
□ トークルーム回答例（購入者側・出品者側のペア）
□ 貼り終えたか確認するチェックリスト
```

**カテゴリを変更すると、価格がリセットされ、必須項目が増える。**
カテゴリを変えてもらったら、セットを丸ごと出し直す。

## 6. 有料オプションは軽く、少なく

上位出品者（評価180件・販売246件）の実例では、オプションは**5つ・500〜2,000円**だった。
500円のオプションは考えずに追加されるが、6,000円のオプションは決裁になる。

- 基本料金はカテゴリの最低価格に置き、**オプションで積む**
- 高いオプション（5,000円以上）は1〜2個まで
- 500〜1,000円の軽いものを必ず混ぜる

## 7. 書いてはいけない表現

フォームの注意書きに明記されているもの。

- 期限を明示しない限定価格（NG:「今だけの特別価格」／OK:「X月までの特別価格」）
- 過度な期待を与える表現（NG:「必ず」「確実に」「〜倍の効果」「最短で」）
- 士業の独占業務（税務・法務・労務）。**該当しないことを本文に明記する側に回る**

## 8. 前の出品のテンプレ文が残る

「見積りにあたってのお願い」には、以前の出品や初期テンプレートの文面
（用途／イメージ・色味／素材提供の有無／著作権譲渡）が残っていることがある。
**新しい出品を作るたびに、この欄を必ず確認して差し替える。**

## 9. 納品ファイルの検証

Excelなどの成果物をセットに含めるときは、渡す前に検証する。

- 数式は `formulas` パッケージで実際に計算し、**セル数と不一致件数を報告する**
- LibreOffice はこの環境では動かない（100秒でタイムアウトする）
- **`wb.calculation.fullCalcOnLoad = True` を必ず立てる。** openpyxl が書き出す
  .xlsx には計算結果のキャッシュが入らず、これが無いと購入者の画面でセルが
  空に見えることがある。立てておけば Excel・Googleスプレッドシート・
  LibreOffice のいずれも、開いた時点で再計算する
- 書き出したら `xl/workbook.xml` の `<calcPr>` に `fullCalcOnLoad="1"` が
  入っているか確認する。数式の検証と同じく、目視ではなく機械で確かめる

## 9.2. 実績が無いうちは「実績風」を作らない

上位出品者の画像は、受注した資料のサムネイルを敷き詰めている。あれが効いている本体で、
グラデーションも極太フォントも飾りにすぎない。**同じ見た目にしたいからといって、
架空の顧客名・ロゴ・案件名を入れた画像を作らない。** 購入前に中身を聞かれた時点で終わる。

代わりに置けるもの：

| 使えない | 使える |
|---|---|
| 架空の受注実績・顧客ロゴ | **この出品用に作った制作サンプル**（「サンプル」と明記する） |
| デザイン歴◯年（事実でない） | 建設コンサルタント15年／公共案件の技術提案書（事実） |
| 「PRO認定」等の未取得バッジ | 対応形式チップ（PowerPoint / Word / PDF）など事実のみ |

## 9.5. 動画は「押し出す」ものではない

ココナラの動画欄は **YouTubeのURLしか受け付けない**。mp4を直接は上げられないので、
書き出したファイルを本人のチャンネルへ上げてもらい、そのURLを貼る。

- **「画像よりも動画を優先して表示する」は原則OFF。** 欄の注意書きに
  「『動画・アニメーション・撮影』『音楽・ナレーション』はこちらを推奨します」と
  書かれている。資料制作や事務代行では、1枚目は静止画のままにする
- ココナラが公開している**おすすめ順のスコア3項目**（サービス情報の充実度／
  プロフィールの充実度／購入後の満足度）に、動画は挙がっていない。
  **動画は順位を買わない。** ページを開いた人の理解を助けるだけ
- 音は入れない。BGMは権利の確認が要る。ナレーションは本人の声で後から重ねる
- 静止画で足りる話を動画にしない。**動きでしか説明できないものだけ**入れる

順番としては、画像を埋める → トークルーム回答例を埋める → プロフィールを埋める、
のほうが先。動画はそのあと。

---

## 10. 出したセットは記録に残す

出品を1本公開したら `_notes/coconala-launch-plan.md` の進捗ログに、
**公開日・出品ID・カテゴリ・価格**を追記する。
方針を変えたときは、その根拠になった実測データも残す。
